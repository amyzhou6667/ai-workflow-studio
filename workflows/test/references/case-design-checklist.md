# 测试用例六维设计检查表

> **核心原则**：需求文档可能不够全面，但测试用例设计绝不能缺失关键维度。本检查表用于指导从 PRD 提取并设计扩展覆盖，确保全面覆盖正常、边界、异常、并发及安全性。

---

## 1. 通用六维设计体系 (任何需求必过)

### 维度一：字段级 (Field-Level)
- **空值校验**：必填项留空提交按钮禁用还是报错提示？选填项留空是否允许正常提交并落库默认值？
- **长度边界**：`min - 1`、`min`、`max`、`max + 1` 四件套边界覆盖。
- **字符集约束**：限定字母+数字时，测试纯字母、纯数字、特殊字符、中文、Emoji、首尾空格的校验拦截。
- **唯一性与重复提交**：同名/重复字段二次提交，系统的校验响应文案与状态码。
- **默认值与敏感数据**：字段留空系统补什么默认值；密码/密钥等敏感字段是否掩码，初始/重置密码生成规则。

### 维度二：操作级 (Operation-Level)
- **快速/重复提交**：连续点击、网络慢时连点（防抖/防重机制），验证后端是否出现重复数据。
- **中途取消与离开**：表单填写一半点击取消/返回/刷新，已填数据是否清空、是否残留脏状态。
- **幂等性验证**：同一写操作/导入操作二次执行，结果是否保持幂等无副作用。
- **列表三件套**：分页查询、条件筛选、多字段排序及其笛卡尔积组合，空列表首屏与缺省占位图。

### 维度三：权限与隔离级 (Permission & Isolation)
- **入口可见性**：无权限用户访问时是隐藏、置灰、还是点击报错拦截？URL 越权直达是否 401/403？
- **多租户数据隔离**：A 租户能否通过篡改 ID/URL 访问或修改 B 租户的资源？
- **角色权限矩阵**：不同角色（如超级管理员、普通管理员、标准用户、受限用户）的操作权限与访问边界。
- **账号生命周期与异常态**：禁用、冻结、过期账号的操作拦截表现。

### 维度四：状态机与生命周期级 (State Transition)
- **前置状态矩阵**：初始态、处理中、成功、失败、撤回等不同前置状态下的行为验证。
- **状态迁移与逆向路径**：从状态 A 迁移至状态 B 后，能否正常回退/撤销？非法逆向迁移是否被拦截？
- **临界阈值态**：恰好等于临界点（如余额恰等于提现额、库存恰等于下单数、超出 1）的表现。

### 维度五：异常与容灾级 (Exception & Resilience)
- **接口失败/超时**：后端 4xx/5xx 或网络超时，前端友好提示、重试机制与降级。
- **越界与超限**：文件大小超限、导入行数超限、超出限制时的提示文案与拦截。
- **并发与环境干扰**：多人同时操作同一资源时的乐观锁/并发冲突提示。

### 维度六：数据与展示级 (Data & Presentation)
- **UI 与 API 一致性**：页面呈现的数据与底层 Network API 返回的 JSON 字段是否严格一致，有无失真或格式截断。
- **多值与分隔符**：多项标签/角色拼接时的分隔符（全角/半角、逗号/分号）兼容性。
- **长文本与排版**：超长标题/多语言字符下的换行与省略样式截断（`text-overflow: ellipsis`）。

## 2. 澄清问题清单模板 (需求不明确时使用)

在阅读 PRD 时，若遇到以下情况且 PRD 未做说明，须列出澄清问题：
> 固定句式：「当【操作】且【前置状态/角色/数据态】时，预期表现是什么？提示文案是什么？」
1. 空值或默认值缺省时的兜底表现；
2. 无权限用户触达时的入口表现（隐藏 vs 置灰 vs 提示）；
3. 异常状态（如网络断开/服务宕机）时的前端交互机制；
4. 跨租户/跨用户数据隔离规则；
5. 批量/高频操作的防重与限流机制。
